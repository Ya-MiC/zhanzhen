## 1. 核心定位

> **引擎开源（MIT），配方闭源（商业秘密），模板商业授权，数据用户所有**

这是「湛箴」区别于传统审计软件、也区别于纯 SaaS 的核心护城河设计。

## 3. Open Core 双轨模式说明

### 3.1 模式对照成熟先例

| 公司 | 核心开源部分 | 商业闭源部分 | 经验借鉴 |
|------|--------------|--------------|----------|
| **GitLab** | GitLab CE (Core) | GitLab EE (企业版：安全、合规、规模) | 核心功能开源，企业级特性闭源 |
| **Sentry** | Sentry SDK + Server (自建) | SaaS 托管版 + 高级分析/合规 | 自建免费，托管付费 |
| **Grafana** | Grafana Core (可视化) | Grafana Enterprise (认证、报表、插件) | 插件生态开源，高级插件商业 |
| **HashiCorp** | Terraform/Vault/Consul Core | HCP 托管 + Enterprise 功能 | 协议变更 BUSL 引发争议，**湛箴坚持 MIT 不变** |
| **Elastic** | Elasticsearch/OpenSearch | X-Pack (安全/监控/报表) | SSPL 争议，**湛箴避免协议变更** |

### 3.2 湛箴的双轨具体落地

```
┌─────────────────────────────────────────────────────────────┐
│                    公开仓库 (GitHub, MIT)                    │
│  zhanzhen/ (核心引擎)  |  audit-os/ (CLI 参考)              │
│  hermes/ (DSH 插件)    |  audit-os-mobile/ (APK 骨架)       │
│                                                          │
│  ✅ 完整可用的单机版审计工具（免费版对应功能）               │
│  ✅ 开发者可自建、二次开发、贡献 PR                         │
│  ✅ 规则引擎、状态机、存储、OCR 架构全透明                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   商业闭源部分 (私有/付费墙)                  │
│  • 专业报告模板包 (政府/事务所/跨境/银行)                     │
│  • 规则参数配方 (阈值、基准值、权重)                          │
│  • 行业科目映射词典 (55+ 别名表持续更新)                      │
│  • 服务端 OCR 高精度模型/批量管线                             │
│  • AI 助手风格微调管线 (用户私有数据训练)                     │
│  • 云端多租户 SaaS 运营代码 (计费/配额/运维)                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 为什么不选择 AGPL / SSPL / BUSL？

| 协议 | 优势 | 劣势 | 湛箴决策 |
|------|------|------|----------|
| **AGPL** | 防止 SaaS 白嫖核心代码 | 吓退小所用户、贡献者、商业采纳方；法律模糊地带多 | ❌ **拒绝** — 与获客策略矛盾 |
| **SSPL** | 云厂商托管强制开源 | OSI 不认可、社区分裂、Elastic/Redis 前车之鉴 | ❌ **拒绝** — 破坏开源信任 |
| **BUSL** | 延迟开源、商业保护 | 非开源协议、HashiCorp 事件信任受损 | ❌ **拒绝** — 承诺 MIT 永不变更 |
| **MIT (现状)** | 最大采纳度、商业友好、社区信任 | 理论上允许云厂商托管不回馈 | ✅ **坚持** — 靠「配方闭源+模板商业+运营护城河」而非协议 |

> **核心逻辑**：湛箴的护城河不在「代码不被复制」，而在于「参数配方持续迭代」「模板库持续积累」「运营服务持续增值」。代码开源反而建立标准、降低信任成本。

## 4. 用户数据权利条款要点

> 将写入 `PRIVACY_POLICY.md` 与 `TERMS_OF_SERVICE.md`（待新增）

| 权利条款 | 具体承诺 | 合规依据 |
|----------|----------|----------|
| **数据所有权** | 用户财务数据、上传报告样本、OCR 图片，**永远归用户所有** | 《民法典》物权编、《个保法》 |
| **使用权授权** | 用户授权湛箴：「为提供服务必要范围内」处理数据（存储、OCR、规则覆核、报告生成） | 《个保法》第 13 条知情同意 |
| **禁止跨租户** | **绝不**将 A 租户数据用于 B 租户模型训练/基准值计算/任何形式共享 | 审计独立性要求、商业道德红线 |
| **禁止公开训练** | 用户上传的历史报告样本，**仅用于该用户 AI 助手风格微调**，不用于任何公开/共享模型训练 | 《个保法》目的限制原则 |
| **删除权** | 用户随时可一键删除账套/全量数据，30 天内彻底擦除（含备份） | 《个保法》第 47 条删除权 |
| **可携带性** | 支持一键导出全量数据包（JSON + 图片 + 报告），格式开放文档化 | 《个保法》第 45 条可携权 |
| **最小化收集** | 仅收集服务必要字段，不收集设备指纹/位置/通讯录等无关数据 | 《个保法》最小化原则 |
| **加密存储** | 静态加密 (AES-256) + 传输加密 (TLS 1.3) + 租户级密钥隔离 | 《网络安全法》等级保护 |
