# 注册会计师执业边界与合规（CPA_COMPLIANCE）

## 1. 定位：软件是「分析初稿」，不是审计报告

湛箴的一切输出——风险发现清单、序时账草稿、HTML 报告——性质都是**辅助分析的初稿**。

法定依据口径（承 PRODUCT_TIERS.md §4）：审计报告的法律效力仅来源于注册会计师亲笔签名、
盖章及事务所盖章（《注册会计师法》第 25 条）。软件不具备也不谋求任何签发资格；
中国注册会计师审计准则体系下对报告要素、职业判断与证据的要求，均以执业 CPA 的
人工工作为准，软件输出只是底稿素材。

## 2. 执业边界细则

### 2.1 软件能做（全部已实现并留痕）

| 能力 | 落地机制 |
|------|----------|
| 凭证录入、OCR 提取、分类建议 | 每字段带 confidence 与来源快照；低置信度强制转人工 |
| 序时账自动生成 | 科目来自类型映射模板；借贷平衡硬校验后才可确认 |
| 3+12 规则自动覆核 | 输出带规则号/严重度/解释/证据哈希引用的发现清单 |
| 发现处置留痕 | 每条命中必须人工「属实/误报」，处置写事件链 |
| 可追溯底稿 | 报告结论 → 风险编号 → 触发凭证 → 原件 SHA-256 全链可点回 |
| AI 辅助解释与科目候选 | 只读已确认数据；schema 校验；无写通道 |

### 2.2 软件不能做（边界即红线，见 §4 清单）

- **不出具审计意见**——无保留/保留/否定/无法表示意见四类意见型均由 CPA 判断与出具；
- **不替代签名**——任何导出物不含也不得被解读为签字盖章效力；
- **不替代职业判断**——重大错报风险评估、关键审计事项确定、重要性水平最终裁量属于人；
  程序的 rules12 自动校准值只是参考基线；
- **不替代独立性程序**——利益冲突检查、独立性声明、项目质量控制复核均为人工义务；
- **不做发票联网验真**——国家税务系统无公开接口，格式/平衡/重复检测结论不含真伪判断
  （LIMITATIONS.md #4）；
- **不对政府系统自动申报**——无任何申报通道，也不计划有；
- **科目建议 ≠ 会计政策**——模板映射不是贵所的企业会计制度，采纳前必须人工核对
  （LIMITATIONS.md #5）；
- **AI 建议不是事实**——LLM 解释可能含幻觉（schema 校验不是零幻觉保证），只能当线索。

### 2.3 使用者的责任

1. 对输入凭证的真实性、完整性负责——垃圾进垃圾出，程序不会替你发现原件造假；
2. 所有系统建议在采纳进底稿前经执业者复核确认；
3. 保持独立性与保密义务：把客户数据装入本机前，确认符合你所属事务所的信息管理制度
   （本地部署形态参考 [PRIVACY.md](PRIVACY.md)、加固清单 [SECURITY.md](../dev/SECURITY.md) §6）；
4. 底稿归档时保留程序版本号与数据截止时间（报告页自带），保证可复现性。

## 3. 免责声明全文（每份导出报告内置，不可移除）

以下为声明模板的权威全文（源头 PRODUCT_TIERS.md §4.3，本节为同步镜像；修改必须两处同改
并在 PR 关联法务确认）：

```
【重要免责声明】

本报告由「湛箴」审计智能体辅助生成，仅供注册会计师执业参考，构成「分析初稿」性质。

1. 本软件基于用户提供的凭证数据与规则引擎自动分析，不具备职业判断能力；
2. 所有风险发现、异常指标、报告措辞均为系统建议，最终结论必须由执业注册会计师复核确认；
3. 审计报告的法定效力仅来源于注册会计师亲笔签名、盖章及事务所盖章（依《注册会计师法》第 25 条）；
4. 用户应对输入数据的真实性、完整性负责；软件不对因数据错误导致的结论偏差承担责任；
5. 本软件不提供法律/税务/合规意见，相关判断请咨询执业专业人士。

—— 湛箴审计智能体 | 版本 v{version} | 生成时间 {timestamp}
```

落地要求：每份导出报告（HTML/PDF/Word）必须在显著位置包含上述声明，不可移除；
Web 工作台报告页同样常驻「⚠ 报告是分析初稿，不构成审计意见；签字权属于人」提示。

## 4. 红线清单（产品与运营共同遵守）

| # | 红线 | 违反后果的处理 |
|---|------|----------------|
| 1 | 不出具、不暗示出具审计意见或鉴证结论 | 报告文案评审必查项 |
| 2 | 不模拟/预填签名、印章、签字栏 | 导出模板禁止出现签名区占位 |
| 3 | 不宣称「替代注册会计师」「AI 审计报告」类营销话术 | 市场物料法务审 |
| 4 | 不移除/弱化导出物中的免责声明 | 视为破坏合规基线的缺陷级 bug |
| 5 | 不做发票真伪联网查验或冒充验真结论 | 功能层面物理不存在该通道 |
| 6 | 不对政府系统自动申报、不留申报接口后门 | 架构红线，ADR 层面拒绝 |
| 7 | 不跨租户使用用户数据进行训练/基准计算 | 见 ASSETS_AND_LICENSE.md §4 数据权利条款 |
| 8 | 不用单一 prompt 取代「数据模型+规则引擎+人工覆核」三重防线 | 工程守则（总纲 §14 非目标） |
| 9 | 不向无登录保护的公网环境推广生产用途 | LIMITATIONS.md #2 + SECURITY.md §5 |
| 10 | 不在专业判断场景诱导用户跳过 NEEDS_REVIEW 质量门 | 调低阈值需留痕理由（CONFIG.md §3.3） |

## 5. 场景速判表（常见「能不能」）

| 场景 | 判定 | 依据 |
|------|------|------|
| 用湛箴整理底稿，CPA 复核后签发报告 | ✅ 允许，这正是设计用途 | §2.1 全程留痕支撑复核 |
| 把 HTML 报告直接交给客户当「审计报告」 | ❌ 禁止 | 无签字盖章即无效力，且违反红线 #1 |
| 给老板看的内部经营异常分析（非鉴证） | ✅ 允许 | 属管理分析用途，仍须保留免责声明 |
| 采信 AI 科目建议直接入账不复核 | ❌ 禁止 | §2.2 最后一条 + LIMITATIONS #5/#6 |
| 用规则命中清单替代细节测试程序 | ❌ 禁止 | 规则是筛查线索，不是审计证据充分性的证明 |
| 向客户宣称「本系统已验证发票为真」 | ❌ 禁止 | 红线 #5，无验真能力 |
| 事务所内网部署多人分客户使用 | ⚠️ 有条件 | 按 PRIVACY.md §7 一户一实例隔离，且接受无登录边界 |
| 调高覆核阈值让更多凭证免人工直通 | ⚠️ 慎用 | CONFIG.md §3.3：质量门是合规机制不是性能开关 |

## 6. 产品内建的合规机制对照

| 合规要求 | 湛箴的实现 |
|----------|------------|
| 证据可追溯 | 入库锁 SHA-256 + append-only 事件哈希链 + `zhanzhen verify` 自检 |
| 纠错留痕 | 覆核修正写 `voucher.field_corrected` 事件；分录只允许红字冲销 |
| 机器不过信 | `ZZ_REVIEW_THRESHOLD` 质量门；完整性缺失阻断分录确认 |
| 结论可质证 | 每条 finding 带规则号/严重度/解释/证据哈希，处置双选留痕 |
| 输出定性 | 免责声明内置 + 「分析初稿」定位贯穿全部文档与界面文案 |

## 7. 培训与宣贯要求（面向团队推广者）

- 首次使用的执业人员应完整走一遍 USER_GUIDE.md 的示例账套流程，亲眼看到：
  坏凭证被质量门拦截、确认后不可改、每条风险可回溯到原件哈希——理解工具的「诚实边界」
  比记住按钮更重要；
- 团队负责人每年至少一次对照 §4 红线清单自查使用方式与对外话术；
- 新版本升级时阅读 CHANGELOG 的 Security 与 Changed 小节后再决定是否更新生产实例。

## 7b. 底稿归档配合点

湛箴不是档案管理系统，但输出物按「可归档」设计。归档时建议连同以下要素一起入卷：

| 归档要素 | 从哪里取 |
|----------|----------|
| 程序版本 | 报告页脚 `v{version}`（与 pyproject.toml/CHANGELOG 对应） |
| 数据截止时间 | 报告页脚 timestamp |
| 证据完整性证明 | `zhanzhen verify` 的 ✔ 输出截图或文本（含事件条数） |
| 风险处置轨迹 | 报告内每条 finding 的属实/误报记录（导出前完成） |
| 原始凭证 | objects-root 内文件即原件；如需单独交付，核对报告索引的 SHA-256 一致 |

> 注意：会计凭证与底稿的法定保管年限、介质要求以《会计档案管理办法》及事务所制度为准，
> 本表只说明「程序能提供什么」，不替代档案合规判断。
